# Склад-трекер — MVP (QR-инвентаризация)

**Живой демо:** https://qr-sklad-tracker-production.up.railway.app
**GitHub:** https://github.com/valentinlee/qr-sklad-tracker

Учебный MVP по кейсу [kwork.ru/projects/3257860](https://kwork.ru/projects/3257860) —
складской учёт материалов для производства бань-бочек: приход, выдача, перемещения между
постами, возвраты, списания и инвентаризация. Полное ТЗ — `info/tz.md`.

## Запуск

```bash
npm install
npm start
```

Приложение поднимется на http://localhost:3400 (порт можно поменять переменной `PORT`).

## Как устроено

- `server/index.js` — Express-сервер, вся логика (материалы, движения, инвентаризация, CSV).
- `server/db.json` — хранилище данных (простой JSON-файл, для MVP этого достаточно).
- `public/` — фронтенд без сборки: `index.html` + `app.js` (vanilla JS) + `styles.css`.

## Экраны

**Материалы** — список позиций с остатком и меткой «нужно заказать», когда остаток на
уровне минимального порога или ниже.

**Новое движение** — выбор материала, тип операции (приход / выдача в производство /
перемещение между постами / возврат / списание-брак), количество, посты (для перемещений),
комментарий. Приход и возврат увеличивают остаток, выдача и списание — уменьшают (с
проверкой, что на складе достаточно), перемещение только фиксируется в журнале.

**Журнал** — история движений с фильтром по типу и экспортом в CSV.

**Инвентаризация** — ввод фактического количества, автоматический расчёт расхождения
(излишек/недостача) и корректировка системного остатка с записью в журнал.

## Допущение

Реальное сканирование QR-камерой не реализовано — код материала выбирается вручную из
списка. Сознательное упрощение для MVP: логика учёта и расчётов идентична, сканер камерой —
отдельная задача после подтверждения логики заказчиком.

## Деплой

Для Railway: подключить репозиторий, задать команду запуска `npm start`, Railway сам
определит порт через переменную `PORT` (уже используется в `server/index.js`).
